2. ZODB
../../_images/zodb.png
ZODB (Z Object DataBase) est la base de données orientée objet du serveur d’application Zope. Bien que le projet Zope l’utilise comme système de fichiers, elle est néanmoins utilisable indépendamment de ce dernier pour stocker des objets Python.

A la différence d’une base de données relationnelle, une base de données orientée objet est hiérarchique, autrement dit, il s’agit d’une arborescence comme un système de fichiers d’un ordinateur.

@startmindmap

top to bottom direction

* root
** object A
** object B

@endminmap

Stockage hiérarchique d’une base de donnée ZODB

2.1. Objet persistent
Pour persister une entité (un objet) au sein de ZODB, nous allons généralement définir une classe qui hérite de persistent.Persistent

account.py
import persistent

class Account(persistent.Persistent):

    def __init__(self):
        self.balance = 0.0

    def deposit(self, amount):
        self.balance += amount

    def cash(self, amount):
        if amount < self.balance:
            self.balance -= amount

    def __str__(self):
        return f"account={{balance={self.balance}}}"
Ce bout de code déclare une classe qui contient le solde d’un compte en banque et offre deux méthodes pour le manipuler: deposit et cash.

Hériter de Persistent offres quelques avantages:

ZODB persiste automatiquement les changements faits lors de la modification des attributs.

L’instance aura son propre espace de stockage au sein de la base.
Un objet qui n’hérite pas de Persistent sera sauvegardé dans l’espace mémoire de l’objet qui le référence.

Chaque objet aura un identifiant unique de persistance.
Plusieurs objets peuvent avoir une référence vers cette instance.

Cette référence sera toujours vers la même instance même après une sauvegarde et un chargement depuis la base.

Attention

Les classes ne sont pas stockées au sein de ZODB, elles existent uniquement au niveau du filesystem. ZODB ne stocke que le nom de classe au format __module_name__.__class_name__.

2.2. Installation
ZODB est distribué comme n’importe quel package python. La méthode la plus simple pour l’installer et via l’utilisation de pip

pip install zodb
2.3. Création d’une base de données ZODB
Quand un programme (python) veux utiliser une base de données ZODB il doit établir comme pour n’importe quelle autre base une connexion. Afin d’obtenir une connexion à une instance ZODB nous aurons besoin de trois éléments:

Un support de « stockage »

Une « base de données »

Une connexion à celle-ci

import ZODB
import ZODB.FileStorage

storage = ZODB.FileStorage.FileStorage('data.fs')
db = ZODB.DB(storage=storage)
connection = db.open()
Note

ZODB posséde de nombreux plugin de storage. Il existe de nombreuses implémentation (in-memory, filesystem local, base de données type ZEO, filesystem avec compression/encryption, etc.)

Dans ce chapitre nous n’explorerons que le stockage local sur notre filesystem par l’intermédiaire de FileStorage.

2.4. Persister des objets
Pour sauvegarder un objet au sein de ZODB, il nous suffit de « l’attacher » à un autre objet déjà présent dans notre base.

Pour ce faire, l’objet root nous sert de point de départ. Son but est de servir de namespace pour les objets de notre base. Il est de ce fait possible de directement y sauvegarder un objet.

from account import Account

# This is a terrible idea
root = connection.root()
account = Account()
account.deposit(2412.08)
2.4.1. Transactions et ZODB
Maintenant nous avons des objets dans notre noeud root. Toutefois ils ne sont pas persistés de manière permanente. ZODB utilise le mécanisme des transactions et pour rendre nos modifications permanentes il nous faut les valider (autrement dit la connexion n’est pas en auto-commit).

import transaction

transaction.commit()
Note

Si l’on veut « rollback » (annuler) nos modifications il nous faut faire appel à la méthode abort

transaction.abort()
2.4.2. Persister plusieurs objets
Si nous persistons l’ensemble de notre base au sein de notre noeud root son espace mémoire au sein du storage et in-memory prendre très vitre trop de place et sera contre performant.

Il est conseillé d’utiliser des collections à cet effet et plus exactement des objets BTrees. Un arbre binaire de ZODB est un conteneur, un noeud de l’arborescence, qui se comporte comme un dictionnaire à la différence qu’il n’est pas chargé entièrement lors de son utilisation mais à la demande.

Manipulation d’un IOBTree
import BTrees

broot = BTrees.IOBTree.BTree() # equivalent to BTrees.IOBTree.IOBTree()

broot[1] = "Python"
broot[2] = "ZODB"
2.4.2.1. Les BTrees de ZODB
Les BTrees peuvent contenir une collection très large de données de manière efficace. Bien plus que la mémoire (RAM) de la machine ne pourrait en contenir à un moment donnée.

Ils sont intégrés aux mécanismes de persistences pour fonctionner efficacement avec ZODB et son cache objet. De plus la recherche au sein de leurs structure est rapide (un héritage des arbres binaires).

Les BTrees sont disponibles en quatre parfums (flavor):

Extension de BTrees

Type de la clé:Type de stockage

OOBTrees

<Object:Object>

IOBTrees

<Integer:Object>

OIBTrees

<Object:Integer>

IIBTrees

<Integer:Integer>

Note

Les trois derniers sont optimisés respectivement pour utiliser des entiers en tant que clés, en tant que valeurs et en tant que clés/valeurs.

Indication

Un IOBTree est conçu pour mapper des entiers vers des objets en ayant des clés en tant qu’entiers.

2.4.2.2. Persistence via un BTree
Persistence de comptes via un OOBTree
import BTrees
from account import Account

account = Account()
account.deposit(2412.08)

root.accounts = BTrees.OOBTree.BTree()
root.accounts['account-1'] = account
2.4.3. Recherche au sein de ZODB
ZODB ne fournit pas de moteur de requête (query engine). Le principal moyen d’accès aux objets de la base se fait en « tranversant » les objets (par l’accès aux attributs, aux items ou via des appels de méthodes).

La traversée d’objet (Object traversal) est typiquement plus rapide qu’une recherche au sein d’un SGBDOO.

Indication

Nous pouvons créer des BTrees pour constuire des index afin de créer un erzat de moteur de recherche efficace.

Note

Si notre besoin premier pour notre application est le moteur de requête, ou que notre équipe est plus à l’aise avec de tels mécanisme, une base de données Objet n’est probablement pas la meilleure technologie à mettre en oeuvre pour repondre à notre besoin.

2.4.4. 🛬 Aéroports et ZODB
../../_images/airport.jpg
Note

Un aéroport est l’ensemble des bâtiments et des installations qui servent au traitement des passagers ou du fret aérien situés sur un aérodrome. Le bâtiment principal est, généralement, l’aérogare par où transitent les passagers (ou le fret) entre les moyens de transport au sol et les avions.

Nous allons créer une base de données ZODB des aéroports du monde.

Pour ce faire nous allons récupérer les fichiers regions.csv, countries.csv et airports.csv sur le site ourairports.com qui recence les aéroports du monde et dont la licence et dans le domaine public.

À faire

Créer un fichier models.py qui regroupe les classes Region, Country et Airport nécessaire

Créer un fichier import.py qui prend en paramètre un filename et qui import son contenu soit dans un BTree regions, countries ou airports selon le fichier

Créer un fichier search.py qui permet:
de rechercher un pays par son code (FR, EN, GB)

de rechercher une région (FR-IDF, GB-ENG)

de rechercher un aéroport par son identifiant (EGLL, LFPB, LFPG)

Modifier le contenu des aéroport pour contenir une instance de region et de pays par aéroport et non plus uniquement le code.

Indication

utils.py
import ZODB
import ZODB.FileStorage

def connect():
    storage = ZODB.FileStorage.FileStorage('data.fs')
    db = ZODB.DB(storage=storage)
    return db.open()

def get_root():
    return connect().root()
L’utilisation des librairies python argparse et csv.DictReader est conseillée.
